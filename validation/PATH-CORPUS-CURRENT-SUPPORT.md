# Independent path corpus: current synthetic support

`validation/path-corpus-support-v1.json` is generated by
`python tests/path_corpus/generate_support.py --out NEW_JSON` on Linux. It binds
each project-owned synthetic host to exact source hashes and records the public
command, oracle, Python and platform identities. It contains no source text,
private data or claimed application benefit.

The current Linux CPython 3.12.3 run reports six path-input hosts. Opaque and
ordinary-package hosts return `insufficient_evidence`; the simple callback-poor
host returns `deterministic_rejection`; the arithmetic host remains
`insufficient_evidence` pending complete source-scope review; the supported
flat Python host requires review at path-only inspection; and Go source
returns `incomplete_analysis`. Every case reports target execution and mutation
false. Path-only results are separate from the connected synthetic test module,
which qualifies discovery, source-bound offline review, exact-scope planning,
baseline, apply and modified verification on an independent host. It checks
the public CLI with externally supplied review and scope files through owned
plan creation, plus off/shadow/active one-effect observations, policy/effect mutations,
baseline and apply interruption/resume, dirty Git conflicts, post-apply
conflicts, tampered on-disk receipt rejection and forged external baseline
receipt-anchor rejection during interrupted recovery. Its full case count and exact
test hash are in the generated JSON.

The separate corpus oracle supplies an independently anchored, complete A–M
negative source review for the deterministic arithmetic host. Its outcome is
`no_useful_placement` within the enumerated source and configuration scope;
the plain path-inspection command still reports `insufficient_evidence` until
that review is supplied. This is not a claim of global absence.

The JSON `unrun` field still lists target-native verification, installed host
lifecycle, hosted Python matrix, JavaScript/
TypeScript, live provider benefit and activation. The connected test uses the
trusted-host synthetic verifier's injected runtime; it does not qualify
application startup or production exposure. Independent review is required if
both a host and its oracle change.
