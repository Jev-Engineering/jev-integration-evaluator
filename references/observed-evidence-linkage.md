# Frozen implementation and study linkage

The `observed-*` commands freeze an exact applied implementation, reviewed placement set, study arms, runtime configuration, rubric, model, policy, environment, and optional monitor plan. The caller must retain the expected study, placement, implementation verification receipt, link, collection request, and collection digests outside the files being checked. `observed-link` accepts only a verified applied bundle whose implementation receipt is externally anchored. A changed owned source byte, environment, study, placement, model, policy, rubric, or monitor plan requires a fresh link.

The placement-set record is an independently reviewed identity envelope with exactly one selected candidate, the reviewed inventory hash, and a `selection_sha256` retained by its reviewer. This version links one implementation bundle and one placement only; composite placement sets are unsupported. The command validates its digest and candidate/inventory equality. It does not independently authenticate the external selection decision. The implementation verification receipt remains a synthetic host check; the link reports `verified_synthetic` wiring and `not_tested` provider connectivity.

`observed-collect-offline` requires a separately approved SHA-256 digest of the complete request, including its frozen link, fixture and independent label digests, pair/call/cost/failure bounds, and `egress: false`. Its adapter returns only reviewed, finite fixture outcomes. It does not run a target or provider. Each scheduled test pair remains in the denominator. Missing labels, fixtures, budget, or outcomes produce an incomplete collection. Timeouts and failures remain measured failed outcomes. The independent labels supply expected outcomes; fixture outputs cannot award themselves success. This is a synthetic orchestration qualification only. The package supplies a bounded host adapter interface below, but no concrete live adapter, live egress authority, independent observed labels, or observed benchmark.

The additive Python API `host_collection.collect_host_pairs` accepts a caller-owned `PairedHostAdapter` and invokes its `run_pair` once per scheduled pair. The adapter owns private task input lookup, baseline/treatment execution, its durable attempt ledger and per-pair cost enforcement. This package supplies no concrete provider or target adapter and no CLI for live execution. The request binds the exact frozen link/study, input-manifest and independent-label hashes, adapter implementation and host-scope digests, pair/call/cost/failure bounds, and an optional egress-grant hash. The complete request hash must be retained and approved independently of the caller; passing a freshly self-computed hash is not approval. Observed requests additionally require an exact independently retained egress grant. A synthetic request cannot carry egress authority.

The collector reserves one pair call and its maximum cost before invoking the host. It checks the implementation link after each call, then validates both outcomes and their receipt hash. An adapter exception, malformed response, or over-cost pair returns an incomplete unresolved report and stops further invocation. Post-call source drift also stops further invocation, then raises a link-drift error instead of returning a current evidence report. Unresolved effects require host-ledger reconciliation and a new request. The report retains the full scheduled denominator and never retries a host pair under the same request. Even a complete observed-mode return is labeled `observed_collected_unverified_origin`: the caller must authenticate host receipts and independent labels before any observed-benefit assessment. The repository tests exercise only a synthetic fake host. No live provider or private target was invoked here.

An exact approved request with unknown or insufficient bounds, or an observed request lacking its independently retained egress grant, returns an explicit incomplete report with zero host calls and the full schedule missing. Absent independent labels or host inputs likewise leave their scheduled pairs missing. Malformed or internally inconsistent request identities are rejected before invocation.

`observed-evaluate` rechecks the exact source link and collection seal. Complete synthetic pairs go through the existing frozen study evaluation, which recomputes statistics and deployment gate decisions from raw holdouts; calibration and test data retain the existing study split checks. A supplied gate bundle must match the study's frozen all-gate manifest. A legacy holdout summary is accepted only with its frozen threshold plan and raw holdout rows, and must exactly match recomputation. An incomplete collection cannot evaluate gate evidence. If the link includes a frozen monitor, supplied monitor rows go through the existing monitor evaluator with every scheduled assignment in its denominator; the result records the recomputed monitor report digest. Only a `suspend` recommendation becomes an exposure action; a healthy window never resumes or expands exposure. All outputs retain `supported_benefit: false` and `activation_eligible: false` for this offline path.

The commands are `observed-link`, `observed-check`, `observed-collect-offline`, and `observed-evaluate`; use `--help` for required paths and separately anchored digests. `--monitor-plan` and `--monitor-digest` freeze monitor identity, while `--monitor-rows` and `--monitor-as-of` replay its raw outcomes. Never publish private target files, raw prompts, labels containing personal data, credentials, or receipt archives.
