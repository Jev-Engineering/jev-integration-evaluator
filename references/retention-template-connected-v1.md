# Installed retention connected shadow

Timeout diagnostics use `EvaluationTimeoutError`, a subtype of the existing
`InputError`. Direct transport timeouts, wrapped timeout causes and responses
over the elapsed budget receive this type; other transport failures retain
the generic error. The host audit writes only the fixed type and error-class
metadata when the actual router reports this timeout. Provider exception text
is suppressed. Fresh installed verification of this correction remains pending.

The finite `retention-h-v1` profile binds the reviewed
`retention_host/host_retention_consumer.py`, normal `retention-host` console and
public-only options loader to an exact installed source generation. It reuses
the source binder, owned package/install journey and separate connected
supervisor. The profile is a source contract and grants no execution or egress.

## Operator inputs

Select `--host-profile retention-h-v1` on `template connected-plan` and supply
owner-private external `H_CONNECTED_REF` and `H_AUTH_PUBKEY_FILE` paths. Their
exact hashes are bound into the plan and injected by the supervisor; public
PEM snapshots are rehashed and passed by owned descriptor to OpenSSL. The
separate issuer retains its private key outside the package and child.

The required `H_COMMAND` is the literal `/prune`. Missing choice, `/compact`
and unregistered commands fail closed. Generative compaction is a separate
operation and receives no authority from this template. Required
`H_EFFECT_DIRECTORY` and `H_READY_PATH` identify external raw observations.
`H_TASKS` is `two` or `duplicate`; `H_HOLD` is `0` or `1`, with an explicit
`H_RELEASE_PATH` required for a hold. Optional `SSL_CERT_FILE` is independently
hashed. Unregistered launch fields are refused.

Package/install remain off. Connected shadow requires an exact private
installed binding, authenticated expiring egress grant, matching environment
and dependency digests, one retained durable ledger, and separately signed
launch/stop scopes. The actual credential is resolved only at authorized
launch. Two stable task IDs share at most two calls and one in-flight request.
The original host performs the retention effect once. Its deterministic
consumer rejects loss of pinned items, altered bytes or provenance, over-budget
retention and a wrong mode before committing a fresh owner-private effect.

## Qualification schedule and limits

`tests/test_use_case_retention_connected.py` authors the host before fresh
source scanning/binding, applies reviewed generated edits, builds and installs
both packages, checks installed origins and invokes the normal installed
console outside the checkouts. A separate local TLS issuer/server supplies
synthetic protocol responses. Independent raw retained-item expectations and
read-only SQLite counters cover valid, wrong-model, malformed/timeout, duplicate,
missing private references/credentials and between-task revoked-reference cases.
A final installed-source drift case must fail before any additional launch;
restoring bytes does not restore that installed generation's validity.
Revocation must retain the first effect
and its original ledger charge while refusing the second task. Authentic
stop and matching source rollback complete the journey.
