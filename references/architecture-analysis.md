# Architecture analysis and evidence limits

Python uses the standard-library AST, including function/async/method/nested scopes and module-level statements. It records calls and import aliases, branches/matches, loops/comprehensions, exceptions, returns, comparisons and arithmetic, and assignment reads/calls. The graph resolves conservative same-file and selected import-qualified calls; unresolved targets remain explicit. A repeated qualified declaration receives a stable-with-declaration-order suffix so the graph does not silently overwrite it.

JavaScript and TypeScript use a small read-only wrapper around the trusted TypeScript compiler API. It reads source text with `createSourceFile`, not a target `tsconfig`, language server plugin, import execution, build, typechecker or emitter. It extracts function/method/arrow scopes and their local structure. TypeScript 7.x is deliberately not accepted by this adapter; reverify the compiler interface before upgrading. Absence of Node/the trusted compiler or syntax diagnostics falls back to review-only evidence. The package's pinned parser was chosen for reproducible local support, not as a claim to be the latest TypeScript release.

Other source languages are recognized for inventory and lexical review leads; there is no hidden claim that their ASTs or control flow have been recovered. The agent must inspect source, tests, schemas and traces to complete semantic reasoning. Keywords alone cannot make an approved recommendation. Native JavaScript/TypeScript module-level executable statements outside the captured scopes, Python reflection, monkey-patching, callback registration, framework dependency injection, SQL semantics, C macros, generated code and distributed deployments require further review.

Discovery covers A–M structural combinations rather than just enclosing function names. For example, an opaque function can still be a candidate when a model-produced value feeds an executor, retrieval feeds generation, or graph mutation follows classification. Literal prompts are not included in default logs/reports; read only approved minimal text to evaluate their semantics. The scanner reads but does not execute target code.

The output includes a module map, partial call graph, assignment dependency information, tool/model/retrieval/state flow sightings, side-effect map and decision-point inventory. Branch/loop/exception nodes are not a complete path-sensitive CFG or interprocedural taint analysis. Unknown dependencies must remain unknown. Source signatures indicate potential roles, not proof of an installed provider or factual failure rate.

Default exclusions avoid Git metadata, dependency/build/cache directories, symlinks and sensitive-looking names. User globs, file-size limits and QUICK's file ceiling restrict coverage. A limit, decode error or parse fallback must be disclosed. A partial scan cannot establish exhaustive absence. Mermaid output displays at most 200 nodes; `architecture.json` retains the full bounded map.

For source-specific semantic review, trace the decision producer → evidence transformation → finite options → consumer → side effect → verification/recovery. Read neighboring control branches and tests, consider legal alternatives and abstention, and document the exact source lines/hash. Use an authorized runtime trace when dynamic behavior cannot be resolved statically.
