# Data contracts and traceability

The root `schemas/` files and packaged `jev_integration_evaluator/data/` schemas are identical JSON Schema Draft 2020-12 contracts. `validate --kind KIND --input PATH` checks a JSON object or each JSONL record; config validation additionally applies strict YAML/semantic checks. JSON/YAML duplicate keys and non-finite numeric values are rejected.

**Inventory/opportunity.** Relative source path, qualified symbol, inclusive start/end lines, whole-file and source-span SHA-256, parser, stable candidate ID, A–M/NONE pattern, atomic questions, finite choices, score dimensions and contributions, explicit unknown estimates, semantic review, deterministic alternative, policy/fallback, leverage, experiment and traceability. IDs survive whitespace shifts, not arbitrary renames; duplicate declarations use warned ordinal disambiguation.

**Run.** Required task_id, replicate, task_hash, dataset_id, treatment, code_revision, model_id, policy_version, prompt_hash, mode, success and evidence_type. `prompt_hash` identifies a frozen rubric/protocol, not a changing per-task message. Task input is separately task_hash. Success is boolean and must exist even for failures/timeouts. Optional seed and cluster_id must match across arms. `evaluation_scope` distinguishes task_success from decision_accuracy. Metrics use common declared units; latency is milliseconds and cost is per-task currency consistently selected by the owner. Examples use USD.

**Decision replay.** Required decision_id, source_location, immutable state, question descriptors, primary Choice ID and baseline_decision. Optional ground_truth must be an independently justified label in the same candidate set; no label means no rescue count. Exact offline fixture keys hash `{state, questions, model}`. A missing fixture fails explicitly instead of guessing a response. Remote replay additionally checks authorized maximum calls and a conservative total spend envelope before any request.

**Trace.** Match source file, symbol and source_sha256. Record stable task identity, observation time/state hash, latency, optional actual outcome, calls/tokens/retries and branch. Hash-chained runtime envelopes are verified before unwrapping; hashed task IDs preserve grouping without exporting plaintext IDs. Comparison/error metadata is not a completed-decision observation. A trace failure rate is observational and does not establish a treatment effect. Mark synthetic events explicitly; a mixed synthetic/observed source cohort is rejected and synthetic traces cannot create Tier 3. Unmarked legacy traces are treated as caller-declared observations, not independently authenticated data.

**Review.** Map real candidate IDs to exact source hash, reviewer, explicit approved boolean, reasoning and optional fully explained dimension/estimate changes. Unknown candidates/fields and stale hashes are rejected. Mark estimates as measured, assumed or synthetic in provenance with units, denominator, data/version and limitations. Never supply fabricated values to force an optimizer result.

**Activation.** Explicit host approval/calibration flag, pinned model, policy version, question hash, threshold hash and held-out evidence reference. The reference is not self-validating; the trusted host must review and restrict it.

**Patch plan.** Repository identity, opportunity IDs, old/new content hashes, diff and new content, canonical digest and exact local-change scope. Planning is not application or authorization. Only the approved digest can be applied to unchanged target files.

**Artifact receipts.** Integration manifests, test receipts and outcome receipts carry candidate_id, source/source_sha256 and experiment_id. Test receipts state test_id and passed/failed/timeout/not_run; outcome receipts embed the comparison result and valid disposition. `link` records exact file hashes into the source-to-experiment chain without granting authority. Use templates and retain original files so the hashes can be independently verified.
