# Where JEV should not be inserted

Exact computation belongs in exact code: arithmetic, sorting, parsing, JSON/schema/type/syntax validation, hashes and signatures, file existence, numerical thresholds, fixed lookups, exact dates, database joins, deterministic state transitions and permission checks. Inspect an exit code deterministically; use semantic verification only for the separate question of whether the user's actual objective was accomplished.

`deterministic_alternative` is `none`, `weak`, `equivalent`, `preferred`, or `mandatory`. Preferred/mandatory alternatives and the NONE pattern force Tier 0 even if a score is otherwise high. A review cannot waive a discovered pure deterministic anti-pattern by changing weights. A reclassification needs corrected source analysis and supporting evidence.

Do not replace a generative model with JEV for code, long plans, SQL, shell commands, essays, creative text or summaries merely to include JEV. A generator may create candidates; JEV may select/evaluate a bounded supplied set; deterministic code validates and executes.

Do not add a remote semantic gate to a hard real-time inner loop. Supervisory, asynchronous or offline classification can be separately evaluated when the deterministic real-time controller remains authoritative. Reject authorization-by-model, truth-by-confidence, automatic merge/purchase/deploy from a score, unbounded retries, state-insensitive decision caches, and ambiguous fallbacks to an unsafe baseline.

A strict regular expression may have imperfect semantic coverage, but that does not justify deleting it. Compare the actual deterministic alternative with the proposed hybrid under the same evidence and objectives. A valid final report may reject every candidate.
