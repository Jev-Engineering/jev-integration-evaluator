# Opaque-name discovery and review example

This assistant-authored synthetic host is not the independently authored corpus
required by issue #9. `host/opaque.py::z93` delegates to `a17`, a keyword queue
selector. Neither name supplies a discovery keyword. `r22` is only a dictionary
sighting; the fixture lacks the complete implementation host bindings.

```bash
python -I scripts/run_capability_demo.py --out /new/private/discovery-demo
```

Run from the trusted evaluator checkout on the qualified Linux filesystem
backend. The directory must be new and outside the checkout. Eight private JSON
records cover capabilities, nomination, nominations array, admission, policy,
prepared inventory, semantic review and reviewed inventory. The host is never
imported or executed. The explicit review rejects adding a model to this fixture's
existing rule because no failure or changed requirement justifies that choice.

The checked-in `.example.json` records are historical synthetic schema/provenance
examples for their recorded parser and source. They are not portable approvals:
repository root identity, parser and engine identity must match current discovery.
Regenerate records after moving the host or changing source, engine or policy.

See [the stage contract](../../references/repository-discovery-v1.md) for the
installed command and separate review fields. Binding review remains unperformed;
implementation, mutation, provider execution and runtime activation remain false.
A rejected candidate alone is not a source-reviewed whole-repository conclusion.
